# Accessibility and performance review: excel-exercises-br (Planilhês)

Date: 2026-11-18. Tested the existing production build (`next start -p 3302`, Next 16.4.5). Nothing in the repo or `.next` was changed.
Tools: Playwright Chromium, axe-core 4.x (tags wcag2a/aa and wcag21a/aa), Lighthouse (mobile preset), CDP network capture, a React DevTools-hook commit counter, and keyboard timing in the page.
Scripts, raw JSON and screenshots are in `/tmp/claude-0/-home-user-excel-exercises-br/4fb5383a-9cc7-5eb2-9dd1-c4d53f82e443/scratchpad/revisao/a11y/` (`axe-pages.js/json`, `widgets.js/log`, `net.js/json`, `latency*.js/json`, `mobile-panels.js`, `lh/*.json`, `shots/*.png`).

## Summary

Static axe scans look almost clean: the only rule that fails is `color-contrast`, from a single token pair. Lighthouse accessibility is 96–100. **These scores hide the real problem.** The spreadsheet simulator cannot be used with a keyboard alone. The grid traps Tab. Almost every toolbar button and menu item reacts only to `onMouseDown`, so Enter and Space do nothing. Grading results are not announced to screen readers. Keyboard-only and screen-reader users cannot finish any exercise.

Performance is acceptable on desktop. All interactive features ship as one 67 KB-gzip chunk, and supabase and zod load on every page. Every grid commit re-renders every cell, because `Celula` is not memoized. A 50×26 grid needs about 26 ms per arrow or Enter on desktop and about 110 ms with a 4× CPU throttle.

## Findings

### P0: blocks a user group

**A1. The grid's cell editor is a keyboard trap (WCAG 2.1.2).** All exercise pages, plus /, /pro, /desafio and /teste/*.
- Evidence (`widgets.log`): Tab from page start reaches `INPUT[editor-celula]` at stop 22. After that, five Tab presses, three Shift+Tab presses, Escape+Tab and F6 all leave focus on `editor-celula`.
- Effect: the Verificar, Ver dica and Recomeçar buttons, the toolbar after the grid, the footer and the rest of the page cannot be reached by keyboard. In `Grade.tsx` `aoTeclar`, Tab and Shift+Tab call `preventDefault()` in both "pronto" and edit modes, and an effect refocuses the input whenever `ancora`/`modo` changes.
- Fix (`src/components/simulador/Grade.tsx` ~L319 and ~L398): keep Excel's Tab-moves-right inside a selection, but provide an exit. Either:
  - make Escape in "pronto" mode release focus and let the next Tab go to the next control (for example, set a `liberarFoco` flag that skips `preventDefault` once), or
  - let Tab at the last column and Shift+Tab at A1 pass through, or
  - add Ctrl+Tab / F6 to move focus to the next region.
- Also document the shortcut in visible help text (the `pointer-coarse:hidden` hint already exists) and add `aria-describedby` on the editor.

**A2. Toolbar buttons, menus and pickers only respond to `onMouseDown`, so Enter and Space do nothing (WCAG 2.1.1).**
- Evidence: each control below was focused by script and given Enter, then Space; nothing opened.
  - `botao-filtro`, `classificar-asc/desc`, `limpar-filtros`, `botao-dinamica`, `botao-condicional`, `botao-grafico`, `botao-validacao`, `botao-circular`, each `seta-filtro-*`, `seta-lista`.
  - CF and chart `menuitem`s: Enter on `[data-regra=menor]` did not open the rule dialog.
  - Sheet tabs (`role=tab`): Enter did not select "Jan".
  - BarraToque buttons and BarraFormatacao (R$, %) buttons.
- The chart overlay has `role="button"` but no `tabIndex`, so it is not focusable.
- Only Ctrl+Shift+L (filter on/off), Ctrl+Shift+4/5 and grid typing have keyboard paths. A keyboard user therefore cannot:
  - open a filter dropdown (no Alt+↓ either),
  - insert a pivot table,
  - open conditional formatting,
  - insert a chart,
  - open data validation,
  - pick from a validation list (no Alt+↓),
  - switch sheets.
- Fix: keep `onMouseDown={e => e.preventDefault()}` so grid focus and selection survive, and move the action to `onClick`. Buttons fire `click` on Enter and Space. Affected locations:
  - `BarraDados.tsx` (`acao` helper, L24–29)
  - `MenuCondicional.tsx` (L98, L119, L135, L148)
  - `PainelGrafico.tsx` (L81, L99)
  - `ValidacaoDados.tsx` (L37, L45, L282, L300)
  - `Grade.tsx` filter arrows (L589) and chart overlay (L640, which also needs `tabIndex=0` and an Enter handler)
  - `AreaPlanilha.tsx` sheet tabs (L135)
  - `BarraFormatacao.tsx` (L32)
  - `BarraToque.tsx` (L31, L39, L48)
  - `AjudaFormula.tsx` (L105)
- Add Excel's Alt+↓ in `aoTeclar`: open `MenuFiltro` on a filter header cell and open `ListaSuspensa` on a validated cell.

**A3. Grading results are not announced, and on a wrong answer focus jumps back into the trap (WCAG 4.1.3).** All exercise pages.
- Evidence: `[data-testid=resultado]` has no role and no `aria-live`, and no ancestor has either. After a wrong answer, `activeElement` = `editor-celula` (`Simulador.tsx` L236), so a screen reader hears nothing. After a correct answer, focus stays on Verificar with no announcement. Screenshots: `shots/resultado-errado.png`, `shots/resultado-certo.png`.
- Fix (`PainelExercicio.tsx` ~L120): keep a permanently mounted `<div role="status" aria-live="polite" aria-atomic="true">` and render the result text into it. A `key={tentativas}` remount can cause missed announcements, so keep the live container stable and change only its children. Do not refocus the grid on failure, or announce first and then refocus.

### P1: serious

**A4. Screen readers get no grid semantics and cannot hear cell values (WCAG 1.3.1, 4.1.2).**
- The only accessible name is `aria-label="Célula B1"` on the hidden editor. The live region (`Grade.tsx` L791) announces only the address ("B1"), never the value or formula.
- There is no `role="grid"`/`gridcell` (`gridRole:false`), and column and row headers are plain `div`s.
- Fix: put the content in the editor label or the live text, for example `Célula B8, =SOMA(B2:B7), R$ 7.355,00`, and include the CF state ("destacado: vermelho") and the filter or validation state. Consider `aria-roledescription="planilha"`.

**A5. Custom menus and dialogs lack dialog/menu behaviour (WCAG 2.1.1, 2.4.3, 4.1.2).**

| Widget | role / name | Focus on open | Escape | Focus return | Arrow keys |
|---|---|---|---|---|---|
| Filter menu (`MenuFiltro.tsx`) | `role=dialog` + label OK | **stays on arrow button**. Tab goes to the next arrow buttons and then the grid trap, never into the menu (DOM order puts the menu after the grid) | closes ✓ | grid ✓ | n/a |
| CF menu (`MenuCondicional.tsx`) | `role=menu`/`menuitem` | **stays on button** | **does not close** | – | **none** (role=menu without roving focus) |
| CF rule dialog (`JanelaRegra`) | **no role / no name** (`<form>`) | value input via autoFocus ✓ | **does not close** | grid (OK) | – |
| CF rule manager (`GerenciarRegras`) | no role / no name | not moved | no Escape | – | – |
| Chart menu (`PainelGrafico.tsx`) | `role=menu` | not moved | **does not close** | – | none |
| Chart Design panel | `section` + label ✓; radiogroup with `role=radio` | – | – | – | **no arrows**. All 4 radios have tabIndex 0 |
| Validation dialog (`ValidacaoDados.tsx`) | **no role / no name** (`<form>`) | **not moved** (autoFocus only on the "Lista" source field) | closes ✓ | grid ✓ | tabs: **no arrows** and no `aria-controls` |
| Validation list (`ListaSuspensa`) | axe: `aria-required-children`, `aria-required-parent` ×3, `listitem` ×3, `aria-input-field-name` (button `role=option` inside `li` inside `ul role=listbox`, unnamed) | not moved | **does not close** | – | **none** |
| Pivot field panel (`PainelDinamica.tsx`) | `section` + label ✓; axe clean | – | – | – | Item filter popup (`ItensFiltro`): no Escape, no role |

- Fix:
  - Give the dialogs `role="dialog" aria-modal="false" aria-labelledby=<title p id>`. Move focus into each popup on open and return it to the trigger or grid on close. Add a shared `useEscape(fechar)` to the CF menu, rule dialog, manager, chart menu, list and pivot item filter.
  - Render `MenuFiltro` next to its trigger in DOM order, or move focus into it with `useEffect(() => ref.current?.querySelector('input,button')?.focus())`.
  - For `role=menu`, implement roving tabindex with Up/Down/Home/End, or drop the menu roles and use a plain disclosure list of buttons.
  - For the list, use `ul role=listbox aria-label="Itens da lista"` with `li role=option` directly, and give it arrow-key and Enter handling.
  - For radiogroups and tablists, use roving tabindex with arrow keys (`PainelGrafico.tsx` L182, `ValidacaoDados.tsx` L145).

**A6. Pivot panel keyboard alternative exists but has gaps.**
- Good: the field checkboxes plus "⋯ Mover para" `<select>` let you build the pivot without drag-and-drop. Space on Região and Valor gave `linhas=Região`, `valores=Soma de Valor`.
- Bad:
  - The pivot cannot be **created** by keyboard (A2: `botao-dinamica`).
  - The "⋯" select is `opacity-0`, so its focus ring is invisible (computed opacity 0; `shots/pivot-mover-focus.png`; WCAG 2.4.7).
  - There is no Escape on the item filter.
- Fix (`PainelDinamica.tsx` L252): add `focus-within:ring-2 focus-within:ring-success` on the wrapping `span`.

**A7. The filter menu overflows the viewport on mobile.**
- At 360 and 390 px, opening the column-B filter gives `scrollWidth = 437`, so the page scrolls sideways and the menu is cut off on the right (`shots/m360-menu-filtro.png`).
- Cause: `left` is clamped to `larguraTotal - 240` (the grid's full width), not the visible width. In `Grade.tsx` ~L798, clamp to `gradeRef.current.clientWidth - 240` or position with `right: 0` on small screens. All other pages and panels showed no overflow at 360 and 390 (table below).

### P2: moderate

**A8. Text contrast fails narrowly (axe `color-contrast`) on every exercise page, /teste and /desafio** (4–18 nodes per page; full list in `axe-pages.json`).
- `text-zinc-500` (#71717b) on `--color-bg` #f7f7f2 = **4.49:1**: breadcrumbs, "0 de 3", the keyboard hint, /desafio links.
- Grid column headers on `--color-header` #f0efe8 = **4.18:1**.
- Fix: in `src/app/globals.css`, darken muted text to zinc-600 (#52525c), which gives 7.18 and 6.70. Alternatively, globally replace `text-zinc-500` on page backgrounds (28 files use it), and use zinc-600 for `[data-cabecalho]` in `Grade.tsx`.

**A9. Conditional formatting is shown by colour only (WCAG 1.4.1).**
- The colours themselves pass:

| Style | Text on fill | Ratio |
|---|---|---|
| vermelho | #9C0006 on #FFC7CE | 5.92 |
| amarelo | #9C5700 on #FFEB9C | 4.66 |
| verde | #006100 on #C6EFCE | 6.14 |
| Colour-scale endpoints | zinc-900 text | 6.09 and 7.75 |
| Data bar #638EC6 | zinc-900 text | 5.24 |

- A screen-reader user cannot tell which cells are highlighted. Fix: expose the matched rule in the cell announcement (A4).

**A10. Tap targets under 24 px (WCAG 2.5.8; 2.2 AA, not 2.1).**
- Filter arrows are 16×17 (`Grade.tsx` L601) and the list arrow is 18×25.
- Pivot panel: field rows are 20 px tall, the "⋯" select is 24×20, and "Remover tabela dinâmica" is 159×20.
- Chart panel "Fechar" is 55×20.
- Progress-bar step links (`BarraProgressoModulo.tsx`) are 8 px tall, named only by `title`.
- Inline text links in nav and footer are 17–20 px tall.
- Toolbars, CF menu, rule dialog and validation dialog all pass.
- Fix: `min-h-6`, or larger hit areas through padding or a pseudo-element.

**A11. Chart SVG and overlay naming.**
- axe `label-content-name-mismatch`: the overlay `role=button` is labelled "Gráfico 1 (clique para editar)" but contains the chart text.
- The SVG has `role=img aria-label="Gráfico de colunas: Vendas"` but no data. Add a visually hidden data table, or an `aria-describedby` summary of the values.

**A12. Grid re-render cost (performance).**
- Every commit re-renders **all** cells. The hook counter shows 1343 component renders per commit, 1300 of them `Celula`, on every arrow move, keystroke and Enter.
- Fix: wrap `Celula` in `React.memo` with stable callbacks (`onPressionar`, `onEntrar` and `onDuploClique` are recreated on each render). Have cells subscribe to their own value and selection through a selector, or virtualize the rows.
- Latency is in the metrics table.

**A13. Bundle splitting.** See the metrics below.
- The whole simulator is one chunk: `3rpuz2hiz6eoj.js`, 214 KB raw / 67 KB gzip. It holds the formula engine, pivot, chart, CF, validation, admin panel and test UI.
- `SimuladorCarregavel.tsx` lazy-loads it, but it still loads on `/` and `/pro` (home demo and previews).
- `supabase` (39 KB gz) and `zod` (32 KB gz) load on **every** page, including `/trilha`. zod reaches the client through a runtime import of schemas: `grader/conferir-teste.ts` imports `recursosSchema`, used by TesteModulo and Simulador, and `FormContato` uses `lib/contato.ts`.
- Lighthouse "unused JS" is about 108 KB per page: simulator chunk about 50 KB, supabase about 36 KB, react-dom about 23 KB.
- Exercise content JSON is **not** shipped in client chunks. Titles were grepped and found in no chunk, because content arrives through the RSC payload. Each page's HTML is 6–36 KB.
- Fix:
  - `next/dynamic`/`lazy` for `PainelDinamica`, `PainelGrafico`/`GraficoSvg`, `MenuCondicional`, `ValidacaoDados`, `PainelAdmin` and `TesteModulo`, gated on `ferramentas.*`.
  - Move the `recursosSchema` checks server-side, or use `import type` only.
  - Lazy-init supabase (`lib/supabase/navegador.ts`, `lib/conta.ts`) when an account action happens or when an auth cookie exists.

### P3: minor

- **A14.** The focus indicator is the default 1 px outline (rgb 16,16,16). It is visible but thin on dark buttons (`bg-ink` Verificar, `shots/focus-verificar.png`). Add a global `:focus-visible { outline: 2px solid var(--color-success); outline-offset: 2px }`.
- **A15.** Inputs in the CF rule dialog and the validation dialog use `outline-none focus:border-success`, a 1 px border colour change only. That is a weak focus indicator (2.4.7; 2.4.11 in WCAG 2.2).
- **A16.** Unnamed progress-dot links rely on `title` (`BarraProgressoModulo.tsx`). Add `aria-label`.
- **A17.** SEO 63–66 because of `<meta name="robots" content="noindex">`. This is intentional while `INDEXAR_SITE` is off (`app/layout.tsx` L13); it is only a reminder for launch.

## Keyboard-only journeys

1. **Formula exercise** (/exercicios/soma-total-de-vendas). Tab passes 7 header links, 8 lesson links and 5 question pills, then the formula bar, then the grid (22 stops). Ctrl+Home and arrows reach B8. Typing `=SOMA(B2:B7)` and Enter works. **Then focus is trapped:** Verificar cannot be reached by Tab, Shift+Tab, Escape or F6, and Ctrl+Enter is not bound. **The exercise cannot be completed by keyboard.** It worked only after focusing Verificar by script. Also, the cell-editor focus indicator is the green active-cell border, which is fine, but the input itself has opacity 0.
2. **Filter exercise** (/exercicios/dados-filtrar-regiao). Ctrl+Shift+L turns the filter on (4 arrows). The arrows cannot be activated by Enter or Space, and Alt+↓ is not bound. After the menu was opened with the mouse, the menu's own checkboxes and OK were keyboard-operable once focused by script, and the result read "4 de 9 registros encontrados" in an `aria-live` region. Escape closed the menu and returned focus to the grid. **Blocked at "open the menu" and again at "Verificar".**
3. CF, chart, validation and pivot exercises are all blocked at their first toolbar button (A2).

### Grid interaction latency

Measured from keydown `timeStamp` to the frame after the next rAF, with keys spaced 350 ms apart. Page: /exercicios/dinamica-total-por-regiao, with the grid enlarged to 50×26 through response rewriting, plus a pivot (Região/Valor), CF `menor` on E2:E50 and a colour scale on A2:Z50, a column chart, and 37×26 filled cells.

| Scenario | Cells | Renders per commit | Type char (median/max) | Enter commit (median/max) | Arrow move (median/max) |
|---|---|---|---|---|---|
| Base 22×12, pivot only | 264 | 297 (264 cells) | 4 / 8 ms | 8 / 10 ms | 7 / 16 ms |
| 50×26 + CF + pivot + chart | 1300 | 1343 (1300 cells) | 7 / 24 ms | 26 / 32 ms | 26 / 33 ms |
| Same, CPU 4× throttle (mid-range phone) | 1300 | 1343 | 24 / 50 ms | **112 / 136 ms** | **91 / 114 ms** |

- Event Timing at 4×: keydown processing takes 66–110 ms.
- With fast key repeat (unspaced), arrow input queues up: holding → reached 746 ms at 4× (`latency.json`).
- These stay under INP 200 ms, but there is little headroom on low-end Android. Cost is linear in the number of cells, because `Celula` is not memoized.

### axe-core page scans (WCAG 2.1 AA)

- `color-contrast` is the only failing rule. It flags 5–18 nodes on desktop and 4–17 on mobile for every exercise page, /teste and /desafio. `/`, `/trilha` and `/pro` are clean.
- Widget scans:
  - filter menu, CF menu, rule dialog, chart menu and panel, validation dialog and pivot panel: 0 axe violations. Their problems are behavioural (A2, A5), which axe cannot see.
  - validation list: 4 rules fail (A5).
  - chart overlay: `label-content-name-mismatch`.

## Fix priority

1. A1 and A2 together: the Tab exit, `onClick` instead of `onMouseDown`, and Alt+↓. This alone makes every exercise completable by keyboard.
2. A3: a live region for results.
3. A5: dialog and menu semantics, focus-in, Escape and focus return.
4. A7: filter menu clamp on mobile.
5. A4: speak cell values.
6. A8: the muted-text token.
7. A12 and A13: `React.memo(Celula)`, lazy tool panels, and moving zod and supabase out of the global client graph.
